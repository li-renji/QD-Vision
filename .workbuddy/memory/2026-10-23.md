### 教训：rebase 死循环（我自己定位的）
时钟 tick → setTimeMs → setCurrentTime → **clock.rebase()** → 锚点被重置 → 下一帧 delta≈0 → 时间停在第一帧。
「让 setCurrentTime 内部 rebase，时钟写回时锚点自动跟上」这个假设是错的 —— rebase 把**已推进的 delta 一起吃掉**。
修法：区分「外部写入」与「时钟写入」，后者不 rebase。

### 深层教训：测试通过 ≠ 功能正确（本次最重要的一条）
「有 clip 时 e2e 通过」掩盖了时钟推进其实是**靠 rAF 抖动攒出来的**，不是正确的。
根因是「自持基准（anchorTimeMs = nextMs）」与「无条件 rebase（anchorPerfMs = now()）」互相抵消：
- rebase 把 `anchorPerfMs` 重置为「现在」→ 每帧 delta ≈ 0 → 时间停在第一帧
- 有 clip 时 durationMs>0，微小 delta 累积仍能跨过帧边界 → e2e 断言侥幸通过
- 空工程 durationMs=0 → delta 完全为 0 → 1.5 秒后 currentTimeMs 仍是 16ms

**教训**：e2e 断言「时间码变了」太弱。正确断言应是
**「推进量 ≈ 真实经过时间（±20% 容差）」**，且必须覆盖 **durationMs=0 的边界场景**。
弱断言 + 单一场景 = 漏检。
